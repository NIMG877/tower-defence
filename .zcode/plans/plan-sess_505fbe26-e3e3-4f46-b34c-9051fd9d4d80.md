# 阶段三：LLM 生成技能接入 AbilitySystem（天赋式组件，部署时触发）

## 设计要点
- **触发**：天赋规则 `triggers: [OnInitialize]`（枚举已有 =1，部署时派发，休眠重部署会重新触发）→ 步骤 `generate_skill`。零新增枚举/事件/schema 词表——纯数据配置。
- **注入**：生成完成（约 1-2 分钟）后 `ReplaceSkill`（Skills[0]=新技能；不触碰 EntityData，仅本场有效，下场战斗 PreWarm 恢复原技能）。部署后到替换前原技能正常可用，无降级窗口。
- **组件是异步 fire-and-forget**：`OnTrigger` 提交请求即刻完成（不阻塞步骤序列），`OnTick` 轮询驱动状态机——天赋 sp 为 `totalSp=0+Auto+NoConsume` 常驻 active，OnTick 每物理帧可用。
- **防重是承重的**：组件是数据驱动 op（可配任意触发），有未完成任务时忽略再触发，防 OnTick 类配置刷请求。
- **失败语义**：服务端 error/rejected/超时 → LogError（含服务端 issues），不自动重试；实体休眠（死亡/撤退）→ `OnTeardown` 中止在途请求，重部署后规则重新触发生成。
- **生成物生命周期**：组件持有 `_lastGenerated`；新一轮成功替换后 Destroy 上一代；OnTeardown 不销毁（还是当前在场技能）。cfg 由 `FromDto` CreateInstance 产生，运行时 SO。
- **服务端零改动**：诉求文本走 payload `constraints.request`（analyze/generate 提示词已消费），49 pytest 保持全绿。

## 明确不做
- 周期性触发（用户已改为仅部署一次；将来要周期化，天赋资产里加 `loop(count=-1){delay(N), generate_skill}` 即可，运行时已验证支持）
- EntityAbilityRunner / 枚举 / 事件 / 服务端的任何改动
- 生成期间的 UI 反馈（Console 日志足够）
