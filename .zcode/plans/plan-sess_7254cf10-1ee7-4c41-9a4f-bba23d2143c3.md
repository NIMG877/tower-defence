## 目标

给 ability-server 加一个交互式测试入口(CLI):输入一段技能描述 → Agent 免战局快照直接按描述设计技能 → 终端实时打印每轮的思考原文、工具调用与结果、最终产出。既有功能(HTTP API、快照模式、契约)零改动,Unity 侧零改动。

## 现状结论(已核实)

- 实时通道钩子已存在:`_Reporter.report(phase, detail)` → `on_phase` 回调(agent.py:105-121),但只有简短字符串,思考原文/工具参数/结果没有外发。
- 思考原文在每次模型调用后即在进程内可取(`message["reasoning_content"]`,agent.py:259-261,已进 trace)。
- 唯一的硬闸:无 `battleSnapshot` 时 `battle_digest.build` 抛 ValueError → rejected(agent.py:191-195)。`hostAssets` 本来就可选,validator 无宿主时静默跳过边界校验。
- HTTP 路径按设计剥离黑盒(trace/thread 不出服务),所以实时看思考必须走进程内调用,不走 HTTP——CLI 直调 `GenerateService.generate`。
- `evals/run.py` 已有"从 ability.db 读 protocolVersion+opList 组 envelope"的先例。

## 改动清单(约 200 行)

**1. `app/tools.py`(+4 行)**
- 加 `SNAPSHOT_TOOLS = ("compute_cross_items", "entity", "entities_at", "deploy_cells_near")` 常量(名字放在定义处)。

**2. `app/agent.py`(~45 行)**
- `run(..., on_event=None)`:描述模式判定——有 battleSnapshot 走原路径(描述忽略);无快照但有 `request["description"]` 进描述模式;两者皆无保持现状 rejected(battleSnapshot path 报错不变)。
- 描述模式:跳过 digest;`SYSTEM` 追加一段说明(无快照/无宿主、战局类工具已移除、spawnIndex/bulletDataIndex 取 0 占位并在 intent 标注待宿主绑定、避免 apply_animation_override);首条 user 消息改为 `{"mode":"description","designBrief":描述,"constraints":...}`;`tool_definitions()` 结果过滤掉 SNAPSHOT_TOOLS(模型不浪费轮次调死工具)。
- `_Reporter` 扩展 `emit(kind, data)`(与 report 同样的吞异常策略),循环内 3 处外发:`thinking`(复用 trace_entry 那个 dict,round/model/effort/耗时/tokens/思考原文)、`tool_call`(name+原始参数字符串)、`tool_result`(name+模型可见的结果串,含截断/摘要版)。
- `_description_first_user()` 小助手。

**3. `app/service.py`(+4 行)**
- `generate(request, on_phase=None, on_event=None)` 透传。
- **缓存键加入 description**(必须——否则不同描述同 constraints 会命中彼此的缓存,这是正确性修复)。

**4. `app/cli.py`(新文件,~120 行)**
- 用法:`python -m app.cli "技能描述"`(一次性)/ 无参进入交互循环(tty 时逐条输入,Ctrl+C 退出)/ 管道 stdin。
- envelope 从 ability.db 现读(protocolVersion + canonical opList);进程内调 `GenerateService(Config()).generate(...)`,因此自动获得握手、缓存、案例落盘(logs/gen-*.json 含 trace/thread 回放)。
- 实时打印:`[phase] round n model=… effort=…` → 思考块(整块,非 token 级流式)→ `→ 工具名(参数)` → `← 结果` → 结束打印 status/耗时/总 tokens/轮数/issues/ability 完整 JSON;缓存命中打提示(相同描述会命中,改描述即重跑)。
- 不加 `--mock` 旗标(mock 只能改 config 字面值,遵守既定决策);stdout `errors="replace"` 防控制台编码坑。

**5. `tests/test_agent.py`(+5 例,沿用 make_request/tiered_cfg/脚本化 chat_tools 替身)**
- 描述模式全流程 ok(无快照,首条消息含 designBrief 无 battleDigest,路由不变)。
- 描述模式工具表不含 SNAPSHOT_TOOLS、核心工具仍在。
- on_event 三类事件 payload 断言。
- 无快照无描述仍 rejected(老闸保持)。
- service:不同描述不互相命中缓存、相同描述命中(cached=true)。

**6. `ability-server/README.md`**:CLI 用法章节 + 描述模式语义(无宿主边界校验自然跳过、占位约定、缓存键变化、HTTP 契约与 protocolVersion 不变)。

## 边界与不做的事

- 速度优化不在本次范围(reasoning effort 调优仍是挂起项);thinking 为逐调用整块输出,token 级流式需改 llm 层为 stream 模式,不做。
- 无快照时 spawn/bullet/动画引用不做边界校验(既有 validator 行为),由系统提示约定占位;Unity 客户端、HTTP API、契约、protocolVersion 全部不动。
