# 阻挡机制对齐明日方舟——重构计划（修订版）

## 目标
① 彻底删除 JumpMove 跳跃移动系统；② 碰撞半径拆分：静态实体 0.25 不变、可移动实体 0.1（对齐 AK）；③ 阻挡判定与表现对齐 AK：点入圈 0.7071、干员侧最近优先、偏移 0.5 圆边界 + 0.2s 插值 + 稳定阻挡位置、高低台层级；④ 顺手修 3 个确认问题（撤退不解阻挡、超容量留新挤旧、重合无特例）。

可移动半径 0.1 后，AK 全部数值在本项目尺度 1:1 成立：吸附 0.7071（²0.5）、偏移落点 0.5（干员碰撞 0.25 + 敌人 0.1，间隙 0.15 与 AK 完全一致）、多敌旋转触发 0.1（=敌人半径）。

## 一、彻底删除 JumpMove
1. **删 JumpMove.cs**（+meta，guid 795c00352ef2a0b4682efc549590d12c）。全项目无其他代码引用。
2. **3 个史莱姆 prefab 换组件**：Slime_Small/Middle/Large.prefab（Assets\Resources\Prefabs\Monsters\MC\AllTypeSlime\）删除 JumpMove 组件块（fileID 840365125945758641），补挂 NormalMove（guid 6b8f5bd5b58612f44b7e392028029c95，无序列化字段）——否则 Entity.cs:238 拿不到 MoveBase 会误走 InteractableStatic 分支且实体不动。史莱姆此后走地面寻路。用脚本做 YAML 手术，Unity 内需重导入验证。
3. **删跳跃寻路**：MapDataManager.cs 的 AStarWayFinding_Jump（359-497）与 FindNewFrontier_Jump（551-582），连带仅被它们使用的死代码（Change/Distance/HeapClear/HeapPush/HeapPop/heap 字段/AStarProperty/HeapEntry 等）。graph 数组、IsValid、RangeCaculator 被攻击范围/视野/普通寻路共享——保留。
4. **删 MoveAnimationBranch 的 JumpBegin/JumpLoop/JumpEnd**（AnimationMachine.cs:9-11）及 AnimationSet.MoveBranchSlot 对应 case（120-122）。该枚举是纯运行时状态、无资产序列化，删除安全。
5. **保留**：AnimationSlot 枚举的 Jump 三值（位于中段，删除会重编号 AttackRemote/Charge* 等后续值、破坏已序列化的 AnimationOverride 配置）、MovementAnimationGroup.Jump SO 结构与 slime.asset 的 Jump 配置（保留后完全惰性）、Spine 的 JumpStart/JumpEnd.asset、覆盖槽位测试（16 不变）。MoveMethod 数据字段与三档寻路（地面/近地/飞行）与跳跃无关，不动。

## 二、碰撞半径拆分
EntityManager.cs:18 的 `EntityR = 0.25f` 拆为 `StaticEntityR = 0.25f` / `MovableEntityR = 0.1f`。全项目 18 处使用点归类（已普查）：
- **运行时选择（仅 1 处）**：EntityMovement.FindSelfInBlocks（:89）→ `float entityR = _entity.MoveBase != null ? EntityManager.MovableEntityR : EntityManager.StaticEntityR;`（MoveBase 与 InteractableStatic 在 Entity 上互斥绑定，Entity.cs:238-245）。
- **StaticEntityR（1 处）**：EntityManager.cs:72 部署阴影缩放。
- **MovableEntityR（其余 15 处）**：出怪阴影（EntityManager.cs:107）；失衡贴墙收约束（MoveBase.cs:154 系）；寻路清障与拐点修整（MapDataManager.cs:357 传参、MapPathFinder.cs:92/356 及形参下游）；编辑器路径预览链（BlockMapCache.cs:17/33/66 快照、MapCanvasView.cs:296）；测试 parity 夹具（MapPathFinderTests.cs:16 常量 0.25→0.1，否则断言失配）。
- InteractableStatic 里 6 处 EntityR 语义本就是"来贴的移动体半径"，且该函数整体被阻挡重构改写（见下），随新逻辑消失。
- 行为变化说明：贴墙滑动停点从 0.25 变 0.40（离墙更近）、贴边跨格判定带从 [0.25,0.5) 收窄到 [0.4,0.5)、怪物影子变小、寻路更贴拐角——均为半径变更的预期结果。

## 三、阻挡机制重构（InteractableStatic 为重心）
**吸附（敌人侧→干员侧）**：删除 MoveBase.FindEntitiesAroundAndTryToBeBlock 及空置的 BlockOccupationS>=0 死条件、删除 100*Vector2.left 哨兵协议。InteractableStatic.FixedUpdate 在维护通过后，若还有剩余容量：`EntitySelector_Radius(自身位置, camp, false, BlockRadius=0.7071, force:true)` 取敌方候选 → 过滤：有 MoveBase、未被阻挡（其 ResistList 空）、非失衡（FetchAbnormalState(1)）→ **按到干员中心距离升序排序**（AK"优先阻挡离自身中心最近的敌人"）→ 逐个注册直到容量满。**高台层级约束**：干员所在格 highland=true 时整段跳过吸附（地面敌人不再被高台干员挡；空中阻挡模式待飞行单位实装再议）。

**落点与注册（原 TryAddToEntityResistList 改写）**：容量检查 `_blockOccupationNum + 敌人占用 > 容量` → 跳过该候选继续下一个；通过则双向 ResistList 互加、容量累加、敌人 TrySetState(Idle, force)、写敌人稳定阻挡位置、调 BeginBlockOffset(落点)。落点=AK 纯径向：dir=(敌人位置-干员位置)，sqrMagnitude<1e-10 → 落点原地（重合特例）；否则沿 dir 外推到 max(距离, 0.5)；随后按已挡敌人的**稳定阻挡位置**做修正（0.1 内旋转分量 / 0.4 内排斥、0.2 权重混入方向，公式沿用、基准从实时坐标改为稳定位置）。**删除 xFree/yFree 地块轴钳制与 blockMinD 机制**（AK 偏移与地块/碰撞无关；此前"疑似 bug"经复查实为合理的贴墙钳制，按一致性删除）。

**0.2s 插值（MoveBase）**：新增 `BeginBlockOffset(Vector2 target)` + FixedUpdate 内插值（dt/0.2 线性，写 Movement.Position→格位自动刷新）；取消条件=解除阻挡或进入失衡；重复调用从当前位置重启；重合特例不启动。

**维持与解除**：InteractableStatic 维护循环改**正序遍历**（最早→最新），失效/超距（>0.7071，平方比较）/超容量者解除——容量缩减时保留最早挡的（修"留新挤旧"）；解除时通知敌人 MoveBase.RelieveBlock（其内清稳定位置、取消插值）。MoveBase.FixedUpdate 保留"ResistList[0].Stats.IsActive==false→自解"检查。**修撤退 bug**：InteractableStatic.Dormancy 遍历 ResistList 副本逐个通知敌人解除后再清空（现状 Entity.Dormancy 只清自己列表、撤退不置 IsActive=false，被挡敌人会永久卡死）。

既有联动不动：被挡敌人停 Idle、攻击 Tick 照常、ResistFirst 把阻挡者注入候选（无视射程）、近战组攻击动画、WriteBlackboard targetblocked。

## 不做（范围外）
"攻击阻挡的所有敌人"目标数机制（技能层）；隐匿显形联动；空降第二干员挤位（等实测手感再议）；飞行单位与 0.8944 空中阻挡半径（无数据）；数据表零改动。

## 验证
静态走查全部调用点 + 确认 3 个 prefab 组件替换后 Unity 重导入无 Missing Script。Unity 实测清单：①空降干员吸附 0.7071 内敌人、0.2s 滑动到格边落点；②同干员多敌扇形排开；③撤退/死亡干员后敌人立即恢复移动（修 bug 验证）；④地面敌人贴过高台不再被挡；⑤史莱姆改为地面行走、波次正常；⑥击退出 0.7071 脱阻、失衡滑行中不被吸附；⑦技能增减阻挡容量时挤出的是最晚挡的敌人；⑧怪物影子变小、寻路贴拐角符合预期。
